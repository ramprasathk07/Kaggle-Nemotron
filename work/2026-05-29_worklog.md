## Root cause that links every crash

Unsloth auto-patches `SFTTrainer` / `GRPOTrainer` at import time on Kaggle. Its
fused/compiled loss assumes a **pure-Transformer** `lm_head` path: it takes the
model's `last_hidden_state` (dim = hidden = 2688) and applies `lm_head` itself.

**Nemotron-3-Nano is MoE + hybrid Mamba-Transformer and returns LOGITS already**
(dim = vocab = 131072). Unsloth projects a second time → shape clash:

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (750x131072 and 2688x131072)
```

Disabling Dynamo alone does NOT fix it (it's wrong math, not a trace guard).

**Fix pattern (applied to all training notebooks):** purge `unsloth` + `trl`
from `sys.modules`, strip unsloth hooks from `sys.meta_path`, re-import trl clean
→ vanilla TRL trainer. Assert guards it:

```python
os.environ["TORCHDYNAMO_DISABLE"] = "1"
os.environ["TORCH_COMPILE_DISABLE"] = "1"
import torch, torch._dynamo
torch._dynamo.config.disable = True
torch._dynamo.reset()
for _m in list(sys.modules):
    if _m == "trl" or _m.startswith("trl.") or "unsloth" in _m.lower():
        del sys.modules[_m]
sys.meta_path = [f for f in sys.meta_path if "unsloth" not in type(f).__module__.lower()]
from trl import SFTTrainer, SFTConfig  # or GRPOTrainer, GRPOConfig
assert "unsloth" not in SFTTrainer.__module__.lower()
```

Model object stays valid after purge (bound methods unaffected). Still loaded via
Unsloth `FastLanguageModel` — only the *trainer* class is swapped to vanilla TRL.

## File: `nvidia-nemotron-minmax-sft.ipynb` — CREATED + HARDENED

New SFT notebook. Custom `MinMaxSFTTrainer` maximises the **minimum** per-token
log-prob per sequence (worst-token objective), selectable vs mean NLL.

Build pieces:
- Identical env/loading to GRPO notebook (triton wheel, ptxas-blackwell shim,
  offline wheels, Unsloth model load, RSLoRA r=32 targets).
- One **generalized system prompt** for all 7 puzzle categories (general method +
  per-category rules + mandatory `<think>...</think>` then `\boxed{}` contract).
  Used identically at train + eval. (Earlier per-category routing was dropped at
  user request in favor of a single generalized prompt.)
- Assistant-only label masking (`-100` on system+user), `CompletionOnlyDataCollator`.

### Why the previous run wasted a full week of quota
| Killer | Detail | Fix |
|---|---|---|
| OOM after hours | `F.log_softmax(logits.float())` = fp32 `seq×131072` ≈ 4.3 GB extra; long-seq batch late in run tips past 96 GB | fused `F.cross_entropy(reduction="none")` — no full-vocab fp32 tensor |
| Wall-clock kill | 9500×2ep×seq8192 ≈ 19k steps on 30B → >12 h → session killed | `SUBSET_N=3000` + 1 epoch + `TRAIN_MAX_LEN=4096` |
| No early signal | failure only discovered after burning quota | `SMOKE_TEST` 64 rows / 8 steps (~10 min) |
| Crash = total loss | no checkpoints | `save_steps=100` + auto-resume |

### Compute-safety knobs (single cell, top)
`SMOKE_TEST` · `SMOKE_ROWS/STEPS` · `SUBSET_N=3000` · `NUM_EPOCHS=1` ·
`MODEL_MAX_LEN=8192` vs `TRAIN_MAX_LEN=4096`.

### Loss selector
`LOSS_MODE = "mean" | "minmax" | "blend"`. **Default `mean`** (minmax trains
1 token/seq = ultra-sparse gradient = risky on locked quota). Get a `mean`
baseline first, then experiment.

### Workflow
1. `SMOKE_TEST=1` → run all (~10 min). Watch: `SFTTrainer module: trl...`,
   length histogram (p50/p90/p99), `PEAK VRAM`.
2. If `p99 ≪ 4096` → lower `TRAIN_MAX_LEN` (biggest mem+speed lever), rerun dataset cell.
3. Smoke green → `SMOKE_TEST=0` → rerun from knobs → real run.

## File: `nvidia-nemotron-raft-reinforce-rej.ipynb` — CREATED (NEW)

RAFT (Dong 2023, 2304.06767) / Reinforce-Rej (Xiong 2025, 2504.09118).

Loop: **sample N rollouts/prompt (T=1.0) → verify each → filter by pass-rate p
→ SFT on kept-correct** (self-distillation; STaR / ReST-EM).

- `RAFT_MODE="raft"` — keep top-k correct/prompt, drop p=0 (all-wrong).
- `RAFT_MODE="reinforce_rej"` (default) — also drop p=1 (all-correct, zero signal).
  Xiong's finding: GRPO's edge = implicit zero-gradient-prompt filtering, not
  reward normalization.

Why over GRPO: sidesteps the entire fragile RL-loss class. Just generate +
verify + plain SFT. Reuses the GRPO **verifier verbatim** (per-type classify,
brace-balanced `\boxed{}` extraction, numeric/integer/string match) + the
memory-safe vanilla-TRL SFT path.

### Compute-safety specials
- **Rollout cache** `outputs/raft_rollouts.jsonl` — sampling (the expensive part)
  survives an SFT crash; reused unless deleted.
- **Sampling-time estimate printed** — extrapolates measured s/prompt to 9500
  prompts *before* you commit to the full set.
- gen-mode toggle: grad-ckpt OFF + KV-cache ON during generation, restored for train.
- left-pad for batched generation / right-pad for SFT loss.
- `save_steps=100` + resume on SFT.

### Key knobs
`RAFT_MODE` · `N_PROMPTS=400` · `N_ROLLOUTS=4` · `GEN_MAX_NEW=1024` ·
`TOP_K_KEEP=1` · `KEEP_FORMAT_VALID` · `NUM_EPOCHS=2` · `TRAIN_MAX_LEN=4096`.
`lr=5e-5` (below from-scratch SFT; RAFT refines).

### Warm-start
Edit `SFT_ADAPTER_DIR` → prior SFT adapter (e.g. minmax output as a Kaggle
dataset). Cold-start fallback auto if missing (works, but weaker).

### Iterate (next session)
1. Upload `outputs/raft_adapter` as dataset, repoint `SFT_ADAPTER_DIR`.
2. Delete `raft_rollouts.jsonl` → stronger model re-samples.
3. Rerun = round 2. all-wrong count shrinks, corpus grows (curriculum climbs).

## Patch 2 (same day) — RAFT smoke run feedback

First Kaggle smoke run of `nvidia-nemotron-raft-reinforce-rej.ipynb` exposed
three real problems. Logged output:

```
Sampling 6 prompts. Type dist: {'Bit Manipulation': 3, ...}
  [1/6] 2.8 min  ~169.3s/prompt  corr_rollouts=0  peakVRAM=70.3GB
Sampling done: 6 prompts x 2 in 15.2 min
EST for full set: 151.8s/prompt -> 9500 prompts ~= 400.5 h at these knobs
Groups: all_wrong=5  all_correct=1  mixed=0
RAFT_MODE=reinforce_rej  -> SFT corpus size = 0 examples
RuntimeError: Empty corpus. ...
```

### Issues
1. **Speed**: 152 s/prompt → 400 h for full 9500. Single-prompt `model.generate`
   on a 30B eager-attn model is the bottleneck. Need batched generation.
2. **Empty corpus**: cold-start LoRA solved 0 of 12 rollouts on 5/6 prompts; the
   one all-correct group was dropped by `reinforce_rej` → 0 examples → crash.
3. **Strict format gate** would filter valid `\boxed{}` answers lacking proper
   `<think>` tags on cold start, compounding (2).

### Fixes applied (cells re-indexed, IDs were null after Kaggle round-trip)
- **Cell index 4 (knobs):**
  - `BATCH_PROMPTS=4` — new knob; batched gen across prompts (~3-5× speedup).
  - `KEEP_FORMAT_VALID=False` default — only enable after warm-start adapter
    consistently emits the strict format.
  - `SMOKE_PROMPTS=8` (was 6) so smoke actually exercises batching.
  - Comment promotes `SFT_ADAPTER_DIR` warm-start as the real fix.
- **Cell index 16 (sampling):** batched `model.generate` with left-padded inputs;
  decodes from the shared `plen` column for all rows in the batch. Also prints
  hit-rate + explicit cold-start warning if 0 correct rollouts.
- **Cell index 18 (filter):** `build_corpus(mode, keep_format)` helper called in
  a fallback chain — try strict first, then drop format gate, then fall back from
  `reinforce_rej` → `raft` (keep all-correct groups). Hard-stop with an actionable
  message only if all three fallbacks yield 0.

### How to re-run
1. Re-upload patched notebook to the same Kaggle kernel.
2. **Strongly recommended:** set `SFT_ADAPTER_DIR` to a real SFT adapter dataset
   (minmax output, prior v13/v9 adapter, or any working SFT adapter). RAFT
   without warm-start is bootstrap-fragile on this benchmark.
3. Re-run smoke. Expect: rate ≈ `prev / BATCH_PROMPTS`, non-zero `corr_rollouts`,
   non-empty corpus.

### If smoke still shows 0 correct rollouts even after warm-start
- Raise `N_ROLLOUTS` to 8 (widens the search per prompt).
- Filter prompts to easier categories first (e.g. only Bit Manipulation) to
  bootstrap, then expand.
- If all three fallbacks in the filter still produce empty corpus, the assert
  now prints exactly which knobs to try.

### Decisions baked into the patch
- Format gate OFF by default (was ON) — chosen to favor corpus non-emptiness
  over format strictness, since SFT itself will teach the format from the kept
  examples. Override per-run.
- Reinforce-Rej still default — falls back to RAFT automatically when needed.
- `BATCH_PROMPTS=4` conservative for 96 GB at `GEN_MAX_NEW=1024`. Tune up on
  spare VRAM, down on OOM. The printed `peakVRAM` in the sampling log is the
  signal.
