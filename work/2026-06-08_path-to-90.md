# Path to 90% — elaborate plan (research-backed)

## Context
Have a **0.85 SFT checkpoint**. In flight: a fresh SFT on merged Tong+Sonnet CoT
(`data_manipulation/merged_sft_tong_sonnet.csv`, 10,297 rows) and RAFT/Reinforce-Rej
on top of the 0.85. Goal: **≥ 0.90 LB**. Question raised: *which other LoRA
targets/layers unlock >90?* Answer below, plus the real levers.

---

## Hard truth #1 — LoRA targets are already maxed; they won't get you to 90

Researched the LoRA-on-hybrid question. Findings:
- **SSM-PEFT** (arXiv:2410.09016) + **MambaPEFT** (arXiv:2411.03855): for Mamba,
  LoRA value lives in the **linear projections** (`in_proj`, `out_proj`). The
  **SSM scan params** (`x_proj`, `dt_proj`, `A_log`, `D`, `conv1d`) are *not*
  amenable to standard LoRA — low accuracy-per-param, sometimes hurts.
- Your 0.85 set already = `self_attn.{q,k,v,o}` (6 GQA layers) + `mamba.{in,out}_proj`
  (46 layers) + MoE `{gate,up,down}` (incl. shared + the 128 routable, via Unsloth)
  + `lm_head` ⇒ **~888M trainable (2.74%)**. That is broad.
- **Submission caps rank at 32** — can't buy capacity with rank.

**Verdict:** adding `x_proj`/`dt_proj` = low-ROI; adding `embed_tokens` = large +
risky; touching the **router/gate is forbidden** (NVIDIA freezes it — modifying
destabilises routing). So **target-set changes give ≪1pp.** Stop optimising here.

### The only LoRA experiments worth a *single* cheap A/B (not a 90% path):
1. **`embed_tokens` add** (input embedding) at the same rank — untied from lm_head;
   tiny chance it helps symbol-heavy categories (cipher/equation). One A/B, keep if >+0.5pp.
2. **Concentrate budget on quantization-sensitive layers** (Nemotron-3 paper §4.2:
   the 6 attention layers + the Mamba layer *immediately preceding* each attention
   layer are kept BF16 = sensitive). Currently LoRA is spread over all 46 Mamba
   layers uniformly. A variant that LoRAs only the 6 attn + 6 pre-attn Mamba at
   rank 32 (rest left frozen) concentrates capacity on the layers that matter.
   Cheap A/B; likely neutral-to-small. **Not the main path.**

---

## Hard truth #2 — 90% is a per-category problem

0.85 overall is **not uniform**. Deterministic-arithmetic families (numeral,
gravity, unit-conversion, base-conversion) are likely ~92–98%; the **hard tail**
(cipher with long phrases, bit-manipulation with complex per-bit gates, equation
symbolic-transform, cryptarithm) is likely ~60–75%. Overall 0.90 ≈ pull the
**bottom 2–3 categories up ~15–20pp** while not regressing the top.

**⇒ The master move is measurement, which we don't have yet.**

---

## The plan (staged, each gated by per-category accuracy)

### Phase 0 — Build a per-category eval harness (DO THIS FIRST; ~30 min GPU)
Without it, every later choice is a guess.
- Hold out ~50 train.csv problems **per category** (never used in any training).
- Greedy-decode (T=0, `max_tokens=7680`, vLLM-or-HF) the **0.85 adapter** on them.
- Score with the existing `verify_answer` + `classify_label` (v19/v20 verifier cell).
- Output a **per-category accuracy table** + dump 10 wrong cases/category.
- This is the dashboard for everything below. Reuse the verifier + generators
  already vendored in `post-training/nemo-v19-sdpg-grpo.ipynb`.

### Phase 1 — Merged-data SFT (in flight) + branch-weight polish
- Train the 0.85 recipe (broad LoRA 888M, LR 2e-4 linear, 1 ep, `max_grad_norm=1e9`)
  on `merged_sft_tong_sonnet.csv`. Diverse 2nd CoT per problem = mild augmentation.
- Add Tong's edge: **branch-weight loss** late in training — upweight tokens where
  the model is confidently wrong, `w = min(1, |log p| / branch_logprob)`,
  `branch_logprob≈1.0`, applied to assistant tokens only (the `branch` mode already
  in v20/v21's `advanced_loss`; gate it on the last ~20% of steps like the blend).
- **Eval-gate per category** vs the 0.85. Expect +1–3pp, mostly on mid categories.

### Phase 2 — Targeted synthetic augmentation (the biggest data lever)
v8/0.85 **skipped augmentation** — that's the documented gap to Tong's higher score.
- For each weak category from Phase 0, **generate 2–5k verified synthetic CoT** with
  the deterministic generators (`data/build_golden_cot_dataset.py` +
  `RLVR/synthetic_problems.py`). Perfect labels, zero noise.
- **Curriculum within a category:** easy instances first (short cipher phrases,
  simple bit gates), then hard — so the model learns the *rule* before hard queries.
- **Oversample** the weak categories 2–3× in the SFT mix; keep the strong ones at 1×.
- Re-SFT from base (not on top — avoids compounding drift), eval-gate per category.

### Phase 3 — RAFT / Reinforce-Rej on the residual (in flight)
- Warm-start the best SFT adapter; sample **8–16 rollouts/prompt** on train.csv +
  hard synthetic; keep **correct** completions from **mixed** groups (drop p=0 and
  p=1); self-distill (mean-NLL). `post-training/nemo-v20-raft-synth.ipynb` does this.
- **2–3 rounds**, curriculum climbing: re-upload the new adapter, delete the rollout
  cache, re-run — solved prompts drop out, harder ones become mixed.
- For the *stubborn* residual where pass@16 ≈ 0 (RAFT gets no signal), this is where
  **Dr.GRPO + SDPG dense reward** (v19, `beta=0`, the fixed v6 GRPO notebook) earns
  its keep — dense self-distillation reward densifies the sparse verifier signal.
  Gate hard: only ship if it beats the SFT per-category (RL can regress a strong base).

### Phase 4 — Pick the per-category best (eval-gate, not inference ensemble)
Eval is a single greedy pass — no self-consistency/voting at test time. So:
- Score every adapter {0.85, merged-SFT, aug-SFT, RAFT, GRPO} on the Phase-0 holdout.
- Ship the **single adapter with the best overall holdout** (best-of-N selection).
- If a later notebook supports it, a **2-adapter best-of** (pick per problem by a
  cheap confidence proxy) is a wildcard — but the contract is one adapter; keep simple.

## Concrete knobs / files
- Eval harness: new `post-training/eval_per_category.py` (reuse v19 verifier+generators).
- SFT: `sft/nemo-v21-minmax-sft-clean.ipynb` → `SFT_DATA_PATH = merged_sft_tong_sonnet.csv`,
  recipe locked to 0.85, optional `branch` late-phase.
- Aug: `data/build_golden_cot_dataset.py --per-category N` (raise N for weak cats).
- RAFT: `post-training/nemo-v20-raft-synth.ipynb` (warm-start 0.85, N_ROLLOUTS 8→16).
- GRPO (residual only): fixed `outputs/nvidia-nemotron-v6-drgrpo-rlvr-05062026_output.ipynb`
  (beta=0, completion 2048, num_gen 4).

## What to NOT spend time on
- Chasing new LoRA target modules / higher rank (capped + maxed).
- Touching the MoE router/gate.
- Test-time sampling tricks (eval is greedy T=0, single pass).
- Wonderland/fantasy prompt wrappers (eval tests rule-following; CLAUDE.md gotcha #10).

## Expected trajectory
0.85 → (merged + branch-weight) ~0.86–0.88 → (targeted augmentation on weak cats)
~0.88–0.90 → (RAFT 2–3 rounds + GRPO on stubborn residual) **~0.90–0.92**, eval-gated.
The single highest-EV action is **Phase 0 (measure) + Phase 2 (augment the weak
categories)** — that's where Tong's hidden points are.
